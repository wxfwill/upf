主题 ​

UPF UI 当前主题链路以主应用写入 :root CSS 变量为准，@das-fed/upf-ui/packages/global/theme 不再注册旧主题规则，但会登记 upf-ui 运行时并向 mframe 暴露默认主题兜底能力。

样式入口 ​

业务应用仍需要先引入 UPF Web 的全局样式入口，它只负责 reset、common style 和基础样式，不负责主题变量生成。

ts
import '@das-fed/upf-web/packages/style'

主应用主题运行时 ​

主题源变量、分类、预设值和缺省兜底规则统一维护在 @das-fed/upf-utils/theme 的 source-variables.ts。examples/BasicApplication/src/theme 是主应用主题管理和主题页实现，主应用启动时执行 themeManager.init()，再通过 initThemeBusAPI() 和 exposeThemeAPIToWindow() 向子应用暴露主题快照与变更事件。

ts
import { themeManager } from './theme'
import { initThemeBusAPI, exposeThemeAPIToWindow } from './theme/theme-bus-api'

themeManager.init()
initThemeBusAPI()
exposeThemeAPIToWindow()

主题变量最终由 @das-fed/upf-utils/theme 写入文档根节点。applyThemeEventToDocument(event, { includeBridges: true }) 会同时输出三类变量：

类型示例用途
源变量--upf-color-primary、--upf-text-primary、--upf-bg-primary主应用和 UPF 组件的统一主题输入
组件运行时变量--upf-button-primary、--upf-message-success-bg已迁移组件直接消费
兼容桥接变量--el-color-primary、--das-ui-color-primary、--upf-primaryElement Plus、das-ui 历史样式和旧页面兼容

组件支持范围 ​

当前 UPF 组件主题已经以 --upf-* 根变量和共享桥接变量为主。按钮、输入框、选择器、表格、表单、弹窗、提示、标签、进度、分页、树、Tabs、滚动条、搜索表单、上传、预览、菜单等组件都会读取运行时变量或桥接变量。

upf/framework/packages/das-ui/packages/global/theme 是组件按需加载和二级主应用 HTML 的公共主题运行时入口。它只负责标记 window.__UPF_UI_USED__、暴露 window.__UPF_UI_THEME__.ensureDefaultThemeStyle，不再恢复旧的 setThemeRule 主题规则。新组件或新样式不要继续向该入口追加主题规则，应优先消费 --upf-* 源变量，必要时在 @das-fed/upf-utils/theme 的桥接清单里补运行时变量。

子应用接入 ​

UPF 子应用或需要完整 UPF UI 主题的业务应用，接入共享同步能力：

ts
import '@das-fed/upf-web/packages/style'
import { initSubAppThemeSync } from '@das-fed/upf-utils/theme'

const disposeThemeSync = initSubAppThemeSync({
  syncOnInit: true,
  includeBridges: true,
})

aoit 当前通过 createDasWebApp 的 theme.glob 接入业务主题文件，并引入 @das-fed/upf-web/packages/style。如果页面内使用 UPF UI 组件，应保留样式入口，并确保主应用主题事件能同步到当前应用。

ts
createDasWebApp({
  theme: { glob: import.meta.glob('@/**/theme/*.ts', { eager: true, import: 'default' }) },
})

c3 当前使用 initHostThemeRootSync，只同步宿主源变量，不向非 UPF 壳注入 Element Plus、das-ui 或 UPF 组件态桥接变量。这适合只读取主应用品牌色、文字色、背景色的场景。

ts
import { initHostThemeRootSync } from '@das-fed/upf-utils/theme/es5'

initHostThemeRootSync({
  debug: false,
})

如果 c3 或其它子应用开始直接渲染 UPF UI 组件，应改用 initSubAppThemeSync({ includeBridges: true }) 或在局部 root 上显式写入桥接变量，否则部分组件态颜色不会完整生效。

静态预设 CSS 与独立运行兜底 ​

内置预设源码维护在 @das-fed/upf-utils/theme/source-variables.ts，@das-fed/upf-utils/theme/presets 只导出按预设名组织好的主题配置，das-ui 构建时会通过 buildPresetThemeCssText() 输出对应静态 CSS 到 @das-fed/upf-ui/dist/presets/。静态 CSS 与运行时兜底使用同一份源变量和桥接清单，新增 --upf-* 源变量后需要确认这里的源码文件和构建后 dist/presets 同步包含该变量。发布产物应包含：

  • theme-default.css
  • theme-cjb.css
  • theme-ssl.css
  • theme-dkh.css

业务明确需要静态预设时，可直接引入：

ts
import '@das-fed/upf-ui/dist/presets/theme-dkh.css'

如果 dist/presets 只看到 theme-default.css，说明 das-ui 构建没有正确复制全量预设 CSS；当前构建脚本应优先用 das-utils/dist/theme 动态生成，失败时回落复制源码 packages/das-ui/presets/theme-*.css。

mframe 子应用独立运行且没有宿主主题快照时，会默认启用 upf-ui 兜底主题。mframe 只写入 __MFRAME_AUTO_UPF_UI_THEME__ 与 __MFRAME_UPF_UI_THEME_OPTIONS__，真正注入由 @das-fed/upf-ui/packages/global/theme 在 upf-ui 加载时调用 ensureDefaultThemeStyle() 完成；mframe 侧也会做一次立即检查和延迟检查，兼容 upf-ui 先后加载两种顺序。未指定 presetName 时，会优先读取 data-theme/data-skin 和 localStorage.upf-theme-config，仍缺失再使用 default；useStoredTheme: false 可关闭本地缓存读取，storageKey 可指定缓存键名。

样式优先级从低到高为：自动兜底 style#upf-default-theme-vars 插在 head 最前面；手动引入的 @das-fed/upf-ui/dist/presets/theme-*.css 正常按加载顺序覆盖兜底，且如果页面已存在显式主题源变量会让自动兜底直接跳过；主应用或子应用主题同步写入的 style#upf-theme-root-vars 会保持在 head 末尾，因此优先级最高。需要关闭自动兜底时，在 createMicroApp 中传 upfUiThemeFallback: false；需要指定兜底预设时传 { presetName: 'dkh' }。

维护要求 ​

  • 不在业务页面硬编码组件库内部变量，优先修改预设主题或共享桥接清单。
  • 新增 --upf-* 源变量时，优先维护 @das-fed/upf-utils/theme/source-variables.ts 中的类型、元数据、分类、预设值或 fallback；BasicApplication 通过共享 getter 自动获得变量标签、分类、导入过滤和归一化结果，完整步骤见 docs/theme-system/07-源变量与api说明.md。
  • 新增源变量后需要验证 workspace 源码消费和构建后 dist/ESM 映射消费，避免本地联调正常但发布产物缺少导出。
  • 新增组件态变量时，同步补组件文档示例和本页支持范围说明。
  • 非 UPF 壳只需要品牌源变量时使用 initHostThemeRootSync；需要 UPF 组件完整主题时使用 initSubAppThemeSync。
