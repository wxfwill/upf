UPF UI 文档部署说明 ​

本文档站源文件位于 docs/upf-ui，技术栈为 VitePress。

本地开发 ​

bash
pnpm install
pnpm docs:upf:dev

生产构建 ​

bash
pnpm docs:upf:build

构建产物位于：

text
docs/upf-ui/.vitepress/dist

如果部署到子路径，需要指定 DOCS_BASE：

bash
DOCS_BASE=/upf-ui/ pnpm docs:upf:build

Windows PowerShell：

powershell
$env:DOCS_BASE='/upf-ui/'; pnpm docs:upf:build

一键部署到 GitHub Pages ​

upf 组件库 GitHub 仓库：

text
https://github.com/wxfwill/upf.git

执行：

bash
pnpm docs:upf:deploy:github

如果希望固定输出 GitHub Pages 直达访问地址：

bash
pnpm docs:upf:deploy:github:url

也可以在根目录一次部署两套文档：

bash
pnpm docs:deploy:github

脚本会执行以下动作：

  1. 使用默认 DOCS_BASE=/upf-ui/ 构建文档。
  2. 克隆 https://github.com/wxfwill/upf.git 的 gh-pages 分支。
  3. 如果远端没有 gh-pages 分支，则创建 orphan 分支。
  4. 将 docs/upf-ui/.vitepress/dist 推送到 gh-pages。

自定义路径：

bash
DOCS_UPF_BASE=/ pnpm docs:upf:deploy:github

Windows PowerShell：

powershell
$env:DOCS_UPF_BASE='/'; pnpm docs:upf:deploy:github

首次部署前需要确认本机 Git 已登录，并且对 wxfwill/upf 有 push 权限。

部署完成后，在 GitHub 仓库 Settings -> Pages 中选择 gh-pages 分支作为发布来源。

部署到公司服务器 ​

公司服务器推荐使用 nginx 静态站点部署。

1. 构建 ​

假设公司访问路径为：

text
https://docs.company.com/upf-ui/

构建命令：

bash
DOCS_BASE=/upf-ui/ pnpm docs:upf:build

2. 上传产物 ​

将以下目录内的全部文件上传到服务器：

text
docs/upf-ui/.vitepress/dist

推荐服务器目录：

text
/var/www/docs/upf-ui

3. nginx 配置 ​

nginx
server {
  listen 80;
  server_name docs.company.com;

  location /upf-ui/ {
    alias /var/www/docs/upf-ui/;
    try_files $uri $uri/ /upf-ui/index.html;
  }
}

如果部署到域名根路径，构建时使用 DOCS_BASE=/，nginx 改为：

nginx
location / {
  root /var/www/docs/upf-ui;
  try_files $uri $uri/ /index.html;
}

发布检查清单 ​

  • pnpm docs:upf:build 构建通过。
  • GitHub 部署前确认远端仓库地址为 https://github.com/wxfwill/upf.git。
  • 访问首页、指南、组件列表、核心组件和 README 页面。
  • 子路径部署时确认静态资源路径包含正确 base。
  • GitHub Pages 仓库已开启 Pages，来源选择 gh-pages 分支。
